# Triple-A 质量计划

[English](aaa-quality-program.md) | 中文

## 概述

本计划把 2026-09-20 的审计转化为一条可执行、可安全跟随上游的路径，使 DeepSeek Harness fork 达到当前领先水平。当前结论是 **FAIL**，不是 Triple-A：范围更广的审计记录了六个聚合任务失败、发布证据不完整，以及运行时和发布决策尚未解决。只有当一个不可变发布候选满足冻结的[质量标准](../../.agent/plans/deepseek-harness-aaa-quality-bar.json)中的每个必需项目、通过上游更新演练，并获得绑定到其提交和证据索引摘要的新独立 PASS 审计时，Triple-A 才成立。

<a id="operating-model"></a>
## 运作模型

本计划为每类事实保留一个所有者。[质量标准](../../.agent/plans/deepseek-harness-aaa-quality-bar.json)拥有客观发布准则。[规范 backlog](../../.agent/backlog.json)拥有任务状态、依赖、分类和唯一下一步操作。[ExecPlan](../../.agent/plans/deepseek-harness-aaa.md)拥有背景、里程碑顺序、决策、恢复方法和累计结果。源审计保留为历史证据，绝不成为相互竞争的实时状态页面。

本计划从证据开始，而不是从修复开始。在修改产品代码前，必须在一个精确提交的干净检出中重现或撤销每项发现。抑制、跳过测试、警告和残留等计数观察，只有在一个规范过程记录其语料范围、提交、环境和结果后才可执行。

每项生产修复在实现前都要在[定制策略](../../.agents/customization-policy.json)中获得独立条目。质量计划条目只拥有规划和治理产物；它绝不代表后续工作认领包源码。

<a id="executive-priorities"></a>
## 执行优先级

1. 建立可信证据：固定一个提交和环境，重现六个失败的聚合叶任务，并运行两次审计都未建立的必需发布任务。
2. 恢复确定性执行：只删除已验证的构建残留，使 spill fixture 可移植，配置固定浏览器，并明确独立命令的前置条件。
3. 闭合维护中的自定义差异：修复构建产物的快照解析，同步持久 shell 文档和理由，并增加必需的无密钥模型可见快照。
4. 解决安全敏感的运行时约定：定义 WebSocket 关闭静止、静态资源符号链接限制、HTTP 请求聚合内存，以及动态扩展信任和 CSP 行为。
5. 恢复架构和生成事实：修复客户端领域所有权、回放世代选择、请求次数行为，并通过所有者重新生成衍生图。
6. 让 fork 治理失败关闭：修复加权审批，拒绝无效定制记录，证明官方镜像身份，并输出可比较的审计指标。
7. 授权发布行为：在打包产物资格验证前决定 fork 包身份和公共源码导出。
8. 按所有者范围分批减少静态债务，然后验证并独立审计一个不可变发布候选。

<a id="roadmap"></a>
## 路线图

| 里程碑 | 可观察结果 | 必需证据 |
| --- | --- | --- |
| M0 — 基线 | 一个干净提交具有完整环境和发现矩阵 | 精确 ref、工具、umask、命令、输出，以及每个已报告失败的分类 |
| M1 — 确定性环境 | 清理准备、约束、spill、浏览器和 hygiene 路径行为可预测 | 干净树约束、两种 umask 的 spill 结果、固定浏览器回放和独立 hygiene 证据 |
| M2 — 自定义差异 | 弹性压缩和 shell 诊断可归属、可移除、有文档且可回放 | 构建路径回放、聚焦测试、同步的所有者文档和无密钥 Session 快照 |
| M3 — 运行时安全 | 关闭、符号链接、内存和动态代码策略具有批准的约定和负向测试 | 屏障、逃逸、并发负载、取消、CSP 和同意证据 |
| M4 — 架构证据 | 领域导入、模块图、回放世代和模型请求与其所有者一致 | 聚焦的图、生成器、快照和预期输出检查 |
| M5 — 治理 | Fork 自动化拒绝所有权、镜像、指标和前置条件漂移 | 有效和无效 fixture，以及顶层工作流或命令执行 |
| M6 — 发布 | 命名空间、仓库身份、源码导出和打包入口获得授权 | 打包清单、publint、发布打包、打包安装和 NodeNext 消费者证据 |
| M7 — 静态强化 | 已弃用读取器、抑制、lint 规则和编译器放宽具有下降的归属债务 | 规范指标、按所有者迁移和已评审探测 |
| M8 — 发布 | 一个候选通过完整矩阵和独立最终审计 | 同一提交的本地和 CI 证据、更新演练、密封评审，以及绑定到候选的带日期 PASS 证明 |

里程碑定义依赖顺序，不承诺日历时间。安全设计可在 M0 后与确定性环境工作并行，但共享包编辑仍须串行，且每项必需人工决策都必须先于实现。

<a id="solution-routing"></a>
## 方案路由

代码变更前使用[改进开发标准](improvement-development-standard.zh.md)。现有仓库检查、工作流、指标、配置和生成器使用 `repository-automation`。网关、文件系统、HTTP bridge、Session、客户端所有权或包导出的缺陷使用聚焦的 `upstream-package-change` 记录，因为官方包拥有这些行为。弹性压缩保留现有的可选 `plugin-and-bundle`；持久 shell 文案保留现有的聚焦上游补丁。

不要创建通用插件、skill 或 fork 专用替代物来隐藏官方所有者缺陷。只有现有已验证字段已经拥有部署选择时才使用配置。只能通过源或生成器修改生成输出。

<a id="progress-updates"></a>
## 进度更新

任务开始时，集成人读取当前指令和完整 ExecPlan，验证持久状态，确认依赖，创建或更新狭窄的定制策略条目，修改 backlog 状态并追加开始事件。在检查点，集成人记录发现和决策，更新唯一下一步操作，并在产物变化时把受影响证据标记为过期。在验证阶段，集成人先追加精确命令或观察记录，再把任务从 VERIFY 移到 DONE。

每次里程碑转换时，仅当执行范围、顺序、验收或人工决策变化时更新本页。更新 ExecPlan 中的进度、发现、决策、结果和恢复。更新 backlog 中的状态、依赖、所有者、分类和下一步操作。为时间线和证据追加 ledger；绝不重写它们来隐藏失败尝试。

第一个排队的 backlog 操作是 `AAA-001:A01`：在不修改产品代码的情况下，选择规划检查点之后的精确基线提交并记录其环境清单。在规划检查点完成验证、提交、推送并转换为 READY 前，它保持 `TODO`。当前任务状态和后续下一步操作仅以 [`.agent/backlog.json`](../../.agent/backlog.json) 为准。

<a id="human-decisions"></a>
## 人工决策

Fork 维护者或相关产品／安全所有者必须在实现或发布前决定以下事项：包命名空间、仓库 URL 和发布权限；WebSocket 逻辑释放还是确认物理关闭；HTTP 聚合内存和准入行为；动态扩展部署、CSP、同意和默认值；`./src/*` 是否为受支持的公共 API；以及英文和中文社区渠道差异是否属于有意本地化。静态资源处理不是开放的信任选项：解析后的目标必须保留在配置根目录内，符号链接逃逸必须失败关闭。

Backlog 记录拥有每项决策的任务。代理可以收集证据并提出备选方案，但没有已记录的人工权限时，不得推断发布权限、接受残余 HIGH 风险或定义暴露部署的安全策略。

<a id="release-stop-conditions"></a>
## 发布停止条件

出现以下任一情况时停止发布：候选提交或工作树不干净且不可归属；必需准则失败、过期、受阻、未执行或静默跳过；模型可见变更缺少必需 Session 证据和同步的所有者文档；HIGH 风险运行时约定未决定或没有负向测试；发布身份未解决；打包安装或必需平台 CI 为红；Session 或循环变更缺少相邻迁移及两个 SDK 投影；或者可选扩展修改官方 preset、绕过公共扩展点，或在移除后使先前 Session 数据不可读。

审计分数、通过的子集或已接受的 HIGH 风险都不能产生 Triple-A 结论。唯一成功停止条件是每个必需质量准则都有当前证据，并且密封候选获得独立 PASS 结论。带日期的仓库审计在仅含文档的证明提交中发布，并记录候选提交和证据索引摘要；除非在该后续提交上重新运行完整质量标准，否则它本身不是已验证候选。
