Audit records are separate JSON files. Parse child reports with `reportSchema`; [report-output.schema.json](report-output.schema.json) is the supported `outputSchema` for one-shot structured children and must still be followed by `reportSchema` validation. Exit 0 means the records are valid and all findings are closed; exit 1 means valid records retain pending work; exit 2 means malformed input or an unsupported parent decision. ## Task delivery ledger

Use `pnpm exec tsx scripts/audit-evidence/task-ledger.ts REQUIREMENTS.json LEDGER.json --require-complete` before reporting a multi-ID objective as finished. The reviewed requirements file has `schemaVersion: 1`, `objective`, `requiredIds`, and `liveRequiredIds`; the separate delivery ledger has the same objective and required IDs, a 64-character candidate fingerprint, and one `items` row per ID. Each row records `state` (`PENDING`, `CODE_DONE`, `LOCAL_VERIFIED`, `LIVE_VERIFIED`, `BLOCKED_EXTERNAL`, or `ACCEPTED`), `liveRequired`, `limitation`, and evidence with `scope`, candidate, command, exit code, outcome, and reference. The command exits 0 only when every required ID is accepted with candidate-bound local evidence and any required live evidence; it exits 1 for a valid partial ledger and 2 for malformed or contradictory records. The reviewed requirements must be kept outside the agent-written ledger so narrowing the ledger cannot hide an omitted ID. A passing record validates consistency, not the truth of its referenced command or the authority that approved the requirements.
