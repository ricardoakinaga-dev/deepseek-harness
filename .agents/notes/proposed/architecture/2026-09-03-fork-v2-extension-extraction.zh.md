# Agent Note: 把 fork v2 实验提取为独立扩展

Status: proposed

[English](2026-09-03-fork-v2-extension-extraction.md) | 中文

## 问题

`deepseek-harness-v2` fork 把有价值的实验与横跨仓库大部分区域的变化和生成的工程产物组合在一起。把它作为长期分支合并会替换当前官方行为，重复 upstream 已经提供的能力，并使每次 upstream 更新都变成跨仓库协调工作。压缩卡死具有纯扩展修复，但其余质量、分层压缩、完整性、脱敏、Web 传输与工作流想法并不共享一个有效包边界。

仓库分支拓扑和定制差异所有权属于独立的流程决策，记录在[上游安全定制分支说明](../../implemented/process/2026-09-20-upstream-safe-customization-branch.zh.md)中。

## 提案

把 fork 当作证据语料，只提取具有具名所有者和可独立测试公共约定的行为。每个切片将成为独立插件或完整能力 seam，并分别发布；一个精简的可选组合包只组合已接受切片。任何切片都不会复制官方 preset、修改 `agent-loop`、创造移除后会变得不可读的必要会话事件，或宣称同进程完整性检查提供沙箱隔离。

提取将按以下依赖顺序进行：

1. 提议 upstream 辅助调用事件，使其记录有效请求控制，并能表示多次压缩调用而不滥用 `compaction/summary.llmStreamCall`。只有该约定落地后，分层摘要器才能成为替代的压缩 Service Provider。
2. 把 fork 的质量框架拆成完整评估 seam：证据与结论的 Service Definition、至少一个可替换本地 Service Provider，以及决定评估是否影响工作流的显式 Consumer。只有定义了可重建事件与投影所有权时，分数才对会话可见。
3. 分别提议 loader 自有的扩展元数据／内容完整性校验与执行隔离。Loader 拥有 manifest（元数据清单）校验和包身份；如果需要降低权限，则由真正的沙箱提供方拥有。
4. 按数据流拆分脱敏。遥测策略将使用现有 `session-telemetry/record` redact waterfall（瀑布式事件）；模型输入与持久化变换需要各自显式约定，并且不得静默改写彼此的数据。
5. 逐项操作比较 Web 传输与工作流控制实验和当前官方 seam。只有通过生命周期与持久性测试证明缺失的操作才会成为聚焦扩展；现有官方行为保持不变。
6. 比较持久终端工具输出与前台 Bash 和 PowerShell 结果 schema。对齐缺口应作为带持久结果元数据的 upstream 变更进入这些工具包；可选插件不得替换已经注册的 `bash` 或 `pwsh` 工具，短暂的通用工具值也不能构成可回放的执行事实。

Fork 的通用执行结果分类器、现有前台执行结果、输出保留／spill、OAuth 支持、快速失败压缩、持久溢出恢复以及生成的仓库分析产物不进入扩展提取，因为官方包已经拥有运行时能力、其余对齐工作需要 upstream 包变更，或该产物属于开发证据而非产品行为。

## 考虑过的替代方案

**把 fork 维护为产品分支。** 被否决，因为其广泛 diff 会让 upstream 成为反复合并的目标而非真源，并把无关实验耦合进每个发行版。

**发布一个兼容性巨型插件。** 被否决，因为质量评估、loader 完整性、脱敏、压缩、Web 传输与工作流控制具有不同的服务、安全边界、持久事实和移除行为。单个包会隐藏不完整 seam，并使配置与失败所有权含糊不清。

**修改官方私有字段或导入 `src/*` 实现模块。** 被否决，因为仅源码路径与私有状态不是已发布约定。此类插件可能在 monorepo 中通过，却在打包安装或普通 upstream 重构后失败。

**用自定义会话事件记录每个插件决策。** 被否决，因为可移除的第三方组合包目前无法通过公共 Session API 追加可忽略的类型化事件。必要的未知事件会使移除包后的旧会话加载失败。

## 验收标准

- 每个提取包都指出它消费的一个公共事件或服务入口，并通过打包安装或真实 Loader 路径冒烟测试。
- 每个模型可见输入与改变行为的结论都可从官方会话事件或已接受的 upstream 事件扩展中重建。
- 每个能力 seam 在被描述为完整之前都包含 Service Definition、Service Provider 与 Consumer 角色。
- 配置暴露每个随部署变化的选择，拒绝未知键，并在最早可解析点拒绝不受支持的引用。
- 生命周期测试覆盖取消、dispose（资源释放）、并发、部分失败以及 dispose 后无工作，且不使用墙钟 sleep 或共享端口。
- 移除组合包后，官方 profile 文件保持不变，每个已存储会话仍可由官方仓库读取。
- `docs/customization/` 下的文档和每个包 README 都指出官方重叠、安装方式、限制以及有意不重复的能力。

## 风险

公共扩展表面可能不足以记录有效请求控制、支持模型输入脱敏或 loader 隔离，因此这些切片可能继续受阻于狭窄评审的 upstream 变化。如果消费方在没有显式预算时启用评估与分层摘要，它们会增加显著 token 与延迟成本。如果文档混淆身份校验与权限隔离，完整性元数据会造成虚假信心。精简组合包减少合并漂移，但仍需针对每个受支持官方版本进行兼容性测试。
