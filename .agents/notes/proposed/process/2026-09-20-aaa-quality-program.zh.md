# Agent Note：以单一 backlog 和冻结标准治理 Triple-A 质量计划

状态：提议

[English](2026-09-20-aaa-quality-program.md) | 中文

## 问题

两份 2026-09-20 审计覆盖不同命令集合，并产生不兼容的分数和结论。仅靠叙述性路线图无法保存依赖、当前证据、一个安全下一步操作，以及历史命令结果与已验证发布候选之间的区别。在报告、路线图和计划中重复任务状态还会产生新的漂移来源。

修复还跨越官方运行时包、自定义扩展、CI、文档、发布元数据和安全敏感行为。一个宽泛的 fork 改进记录会掩盖哪些变更是可移除扩展、聚焦上游补丁或仓库治理。

## 提议

使用 `.agent/backlog.json` 作为唯一可变任务状态所有者，使用 `.agent/state.json` 作为当前指针，使用仅追加 ledger 保存时间线和证据，并使用一个持续更新的 ExecPlan 保存里程碑顺序、决策、发现、恢复和结果。在产品修复开始前，把客观发布准则冻结到带版本的质量标准中。面向维护者的路线图不包含状态，并链接到这些所有者。

在精确提交的干净重现确认前，把每项审计声明视为历史记录或提议。每项生产修复都获得一个狭窄的定制策略记录，其 `solutionType` 由行为和生命周期所有者选择。质量计划治理记录只拥有规划、审计、状态和验证自动化产物。

只有当一个不可变候选对每项必需质量准则都具有当前证据、没有未解决或已接受的 HIGH 风险、成功完成上游更新演练，并在变更哨兵不变的情况下获得新上下文独立 PASS 审计时，发布才获得 Triple-A 标签。带日期的仓库审计在仅含文档的证明提交中发布，并绑定候选提交和证据索引摘要；除非重新运行完整质量标准，否则不得把该后续提交视为已验证候选。

## 已考虑的替代方案

**把较高或较低的审计分数作为目标。** 已拒绝，因为这些分数汇总了不同执行范围，无法识别哪项必需发布属性失败。

**把 Markdown 检查表作为 backlog。** 已拒绝，因为文本无法可靠强制唯一 ID、依赖、一个当前操作，或与运行时状态和仅追加证据保持一致。

**把完整修复登记为一个治理改进。** 已拒绝，因为治理不得拥有产品包源码，而且后续上游提取要求每个运行时差异保留狭窄所有者和方案类型。

**创建通用质量插件或 skill。** 已拒绝，因为仓库自动化拥有检查和工作流，而官方包拥有运行时发现。插件无法安全替代这些所有者，skill 也无法强制运行时或持久状态行为。

## 验收准则

- 质量标准包含稳定的必需准则及其目标、基线状态、证据方法、条件和来源。
- 规范 backlog 包含稳定任务、依赖、所有者、方案类型、验收摘要，并且每项任务恰有一个结构化下一步操作。
- ExecPlan 和运行时状态通过 engineering-framework 一致性检查，并在中断后提供确定性恢复。
- 执行路线图链接到规范所有者，不重复任务状态。
- 每项生产修复在修改包源码前创建或更新自己的定制策略条目。
- 里程碑转换按照不同所有权更新 backlog、ExecPlan、证据 ledger 和执行页面。
- 最终 Triple-A 结论要求同一候选的当前证据、干净的上游更新演练，以及其证明标明候选提交和证据索引摘要的独立 PASS 审计。

## 风险

如果代理只更新文档而不执行下一步操作，持久规划状态可能成为形式负担。因此检查器验证结构，每个 DONE 转换都要求当前证据，而发布结论与进度文本保持分离。

冻结的质量标准可能保留错误准则。修订必须改变版本，记录原因和受影响准则，并重新取得证据；修订不得仅为获得 PASS 而削弱失败目标。

本计划可能扩张为无关清理。Backlog 只保留具有可重现行为、约定、安全、发布或维护后果的发现。仅计数观察在其语料范围和违反的义务明确前，仍是发现输入。
