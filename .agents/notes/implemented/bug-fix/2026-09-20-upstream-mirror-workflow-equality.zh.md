# Agent Note：在定制差异归属前强制官方镜像相等

状态：已实施

[English](2026-09-20-upstream-mirror-workflow-equality.md) | 中文

## 问题

定制工作流会把定制差异与 `origin/master` 比较，但不会抓取或验证 fork 镜像是否与 `deepseek-official/master` 一致。因此 fork 的镜像分支即使偏离官方来源，也可能通过路径归属检查。

## 决定

策略验证器接受 `--require-official-mirror`。启用该模式后，它使用配置的官方远程仓库和 URL，抓取配置的镜像分支，通过精确提交 ID 比较 fork 远程镜像引用与官方引用，并在镜像引用缺失或不同时先于定制差异归属检查失败。工作流在现有策略检查前调用该模式。

验证器导出纯相等检查，并包含匹配、不匹配和缺失引用夹具。该修正仍属于现有上游安全定制治理所有者的 `repository-automation`；它不修改运行时包、已发布 Session 数据或发布身份。

## 备选方案

**继续只与 `origin/master` 比较。** 拒绝，因为它只能证明相对于 fork 的归属，不能证明与官方来源一致。

**在工作流中硬编码官方 URL。** 拒绝，因为策略记录已经拥有仓库身份，远程配置不一致时工作流必须失败。

**比较历史祖先关系而不是精确提交身份。** 拒绝，因为镜像契约要求 fork 和官方分支解析到同一提交，而不仅是共享历史。

## 后果

工作流会执行只读的官方抓取，并在诊断中包含两个引用和提交 ID，以拒绝过期或分歧的镜像引用。离线夹具保护纯相等规则而不依赖网络状态。工作流通道仍需要可访问的官方公开远程仓库。

## 测试

聚焦策略套件通过匹配、不匹配和缺失引用的相等测试，并断言工作流调用 `--require-official-mirror`。实现后还会运行工作流等价命令、顶层定制验证器、成对文档、Note 格式和空白检查。
